# Contributing to Milestone Planner

Thanks for your interest in contributing!

The full contributing guide — development setup, coding standards, testing, and the **mandatory versioning & changelog discipline** — lives in the documentation:

- [Contributing guide](https://docs-milestone.verdet.me/developer-guide/contributing/) (source: [`docs/developer-guide/contributing.md`](docs/developer-guide/contributing.md))
- [Local development](https://docs-milestone.verdet.me/developer-guide/local-development/)

In short: every PR that touches application code must bump `/VERSION` and add a matching `CHANGELOG.md` entry — CI enforces this. Security issues should be reported privately per [SECURITY.md](SECURITY.md), not as public issues.
