# Frontend architecture

How the React SPA is put together: the tech stack, routing without a router, the Zustand stores and their persistence, the API client and transform layer, the Gantt and Kanban internals, the hooks catalog, the utilities worth knowing, and the What-If sandbox. It was moved verbatim out of the repo-root [`CLAUDE.md`](https://github.com/vincentmakes/milestone-planner/blob/main/CLAUDE.md), which keeps the frontend conventions; the design tokens and shared components are in [`UI_GUIDELINES.md`](https://github.com/vincentmakes/milestone-planner/blob/main/UI_GUIDELINES.md).

Code described: `frontend/src/` — `main.tsx`, `App.tsx`, `stores/`, `api/`, `components/gantt/`, `components/views/`, `hooks/`, `utils/`, `contexts/`.

## Frontend Architecture

### Tech stack

React 18 + TypeScript 5.6, Vite 7, Vitest 4, Zustand 5, date-fns 4, react-day-picker 10 (the date fields' calendar, themed by setting its `--rdp-*` properties from app tokens in `DateRangeField.module.css`), CSS Modules. All data flows through the Zustand stores — there is **no query library** (TanStack Query was installed but unused and has been removed; don't re-add it) and **no router package** — `react-router-dom` was removed as unused; there is no route tree.

### Routing without a router

- `src/main.tsx` boots the theme and wires the API client (`configureApiClient`): What-If check + queue from `whatIfStore`, and `onUnauthorized: expireSession`. (The legacy `rd_*` storage migration was removed.)
- `src/App.tsx` renders by branching: `window.location.pathname` exactly `/admin` or under `/admin/` (`isAdminPath`) → `AdminApp` (a fully separate admin-portal app: `AdminLoginScreen` / `AdminDashboard` with tenants/organizations/admins/stats tabs); otherwise `TenantApp`: auth state decides `LoginScreen` vs the main app, with `LoadingScreen` during the initial load and `LoadErrorScreen` (Retry) if it failed, then `WebSocketProvider` → `MainLayout` + `ModalContainer` + `ContextMenuContainer` + `ActivityFeed`. `TenantApp` also owns the `what-if-mode` body class.
- In-app navigation = `viewStore.currentView` (`gantt` | `kanban` | `work` | `staff` | `equipment` | `crosssite` | `archived`) switched by the sidebar; **views are state, not URLs**. `useAllowedViews()` decides which ones the sidebar lists (`VIEW_PERMISSIONS`: `views.*` keys; Gantt always, My Work for anyone signed in) and disables Cross-site while only one site is visible; `MainLayout` falls back to `gantt` when the current view is no longer allowed and re-selects the lowest-id visible site when the current one is gone. `setCurrentView` refuses every view but `gantt` while What-If is active (see [What-If Mode](#what-if-mode)).
- **All administration is one Settings hub** (`components/settings/`), a full-size shared `Modal` with a grouped section list. The sidebar `AdminSection` has a single **Settings** entry, shown when `canOpenSettings(user)` (any section gated by a held key). Sections come from the `SETTINGS_SECTIONS` registry, each with a `permission` (a key, any-of keys, or `null`) mirroring the backend: General `null` (per-browser theme for everyone; instance-wide settings with `settings.general`), Features & defaults `settings.general` (`DefaultsPanel`: the [Settings keys](routes.md#predefined-phases-settings-predefined_phasespy-settingspy)), Roles `roles.manage`, Sites `sites.manage` or `sites.export`, Teams `teams.manage`, Bank holidays `bank_holidays.manage`, Company events `company_events.manage`, Users `users.view`, Skills `skills.manage`, Absence types `absence_types.manage`, Equipment `equipment.manage`, Equipment types `equipment_types.manage`, Predefined phases `predefined_phases.manage`, Project fields `project_fields.manage` (`ProjectFieldsPanel`: built-in labels / Shown switches saved through the two settings keys — a `settings.general` write —, custom fields with drag reorder, per-dropdown items editor with colour and site/team scope), Tags `tags.manage` (flat list), SSO `settings.sso`. Settings → Roles has two tabs: the role list / `RoleForm` with the `PermissionMatrix`, and `ApprovalPoliciesForm`. Add new admin UI as a registry entry + `…Panel` component (no `<Modal>` wrapper), not as a new sidebar item or standalone modal. The General panel reports unsaved changes to the hub (`onDirtyChange`) so switching section/closing asks first. Custom columns stay in the Gantt project panel. Self-service time off is **My absences** (`MyAbsencesModal`, user menu).
- The tenant prefix `/t/{slug}` comes from the URL: `getTenantPrefix()` in `client.ts` prepends it to every `/api/` call. Deep links work because FastAPI's catch-all (prod) or `tenantSpaPlugin` (dev) serve `index.html` for `/t/*` paths.

### Zustand stores (`src/stores/`)

| Store | Persisted | Purpose |
|-------|-----------|---------|
| `appStore` | only `_persistedSiteId` | Domain data (sites, projects, staff, equipment, blocks, vacations, absence types, holidays+date Sets, events + derived `closureIndex` (built in `setCompanyEvents`), users, skills, tags, `projectFields` (fields with their items, loaded with the initial data), `teams` (every site, inactive included), `roles` and `approvalPolicies` (loaded on first use by `useRoles` / `useApprovalPolicies`, not persisted), instance settings), auth state, current site/user (with its `permissions`), critical-path state. Site switch **clears undo history**. Exports only non-array selectors (`selectStaffSiteIds`, `selectStaffTeamIds`, `selectTeamSiteById`, `selectAbsenceTypesById`, `selectCanManageOthersAbsences`) — array selectors were removed because they re-render forever under Zustand 5 |
| `viewStore` | yes | View mode (`week`/`month`/`quarter`/`year`) + a single `cellWidth` (per-mode *defaults* applied on mode switch, then freely zoomed — widths are not remembered per mode), current view, current date (memory-only), resource tab, expansion Sets (persisted: projects/phases/subphases; session-only: staff/equipment/bank-holidays, and `collapsedStaffGroups` — the **collapsed** overview rows, keys `"<level>:<cardId>:<staffId>"`, so the default is expanded; `toggleStaffGroup`, cleared by `collapseAll` / `expandAll`, in neither `partialize` nor `merge`), level-based expand/collapse, scroll position, panel collapse flags, overview toggles (staff/equipment — mutually exclusive), `teamFilters` (header team filter `{teamIds, noTeam}` per tenant + site, same `siteKey` keying, absent = Whole site, sanitised on rehydrate and listed in `merge`), `projectFilters` (the Filter `{optionIds, noneFieldIds, tagIds}` — OR within a field, AND across fields, tags one more bucket — keyed `"<tenant slug>:<site id>"` via `siteKey()` in `utils/tags.ts` (`tagFilterKey` is its alias) — the storage key is per origin, so tenants must not share entries; persisted, stale ids pruned when applied), `ganttGrouping` (project field id) + `collapsedGanttSections` (`field-<item id>`/`none` keys) for the Gantt "Group by", and `ganttColorBy` (project field id or `'tags'`) for the Gantt "Colour by" (independent of Group by), same `siteKey` keying and rehydrate sanitising (`sanitizeProjectFilters` / `sanitizeSiteFieldIds` / `sanitizeSiteColorBy` / `sanitizeCollapsedGanttSections`), not cleared on logout. Persist `version` 2 (`VIEW_STORE_VERSION`): `migrateViewState` drops a version-0 payload's `tagFilters`, `ganttGrouping`, `ganttColorBy` and `collapsedGanttSections` once (2.0.0 — tag-group ids could collide with field ids) and maps a v0/v1 `currentView: 'todos'` to `'work'`; Kanban board prefs `kanbanProjectId`, `kanbanGrouping` (`none`/`project`/`phase`/`assignee`/`customColumn`) + `kanbanGroupingColumnId`, `kanbanMyTodoOnly` (persisted) |
| `uiStore` | no | Active modal + editing context, Settings hub state (`openSettings(section?, intent?)` → `activeModal: 'settingsHub'` + `settingsSection` + `settingsIntent` view/add/edit; legacy modal keys `settings`/`manageSites`/`siteManagement`/`site`/`userManagement`/`manageEquipment`/`predefinedPhases`/`ssoConfig`/`bankHoliday`/`customHoliday`/`companyEvent` are aliases that open the hub at the matching section; `openSettings`, `setActiveModal('settingsHub')` and the alias keys are no-ops while What-If is active), tooltip, drag/resize state, drag indicator, dependency-linking state, phantom-sibling state, context menu, scroll/zoom triggers, resource drag, Kanban card dialog (`openKanbanCardModal`), `modalContext.returnTo` (reopen the previous modal on close, e.g. My absences → absence dialog), `isLoading` / `loadingMessage`, `flashNotice` + `showFlash(message, tone)` / `dismissFlash()` (a detached error with no form to sit in — context-menu deletes, refused dependency links, failed card moves — rendered bottom-right on an opaque `--bg-secondary` surface by `layout/FlashNotice`, auto-cleared after 6 s) |
| `whatIfStore` | no | What-If mode flag, `structuredClone` snapshot of projects, queued operations, `whatIfApplyError` `{applied, total, message}` + `dismissApplyError`, `reset` |
| `undoStore` | no | Undo/redo stacks of project-tree snapshots (max 50) |
| `customColumnStore` | visibility only | Columns, values map (key `"{columnId}-{entityType}-{entityId}"`), per-column filters (`__empty__` sentinel for blanks), visibility |
| `notificationStore` | no | In-app notification inbox (server-owned; not persisted — the bell reloads on mount/focus), `unreadCount`, `panelOpen`; `receive()` upserts live pushes by id: a push not newer than the stored row (equal `created_at` = a repeat) is ignored, a newer one (a coalesced change notification) replaces it and moves to the top, with the unread count adjusted by the difference; `removeLocal(id)` (the bell's ×; a derived row is ignored, the unread count drops when the row was unread) and `clearLocal()` (Clear all) are optimistic, the bell reloads on a failed call. Derived due-soon/overdue reminders are **not** here — the bell merges them in from `useDerivedDueNotifications`, whose dismissal re-derives every mounted copy at once (it subscribes to the dismissal map) |
| `workStore` | no | My Work: `mine` (own requests, My Requests), `toDecide` (My Approvals), `openCount` (the sidebar badge: requests to decide), `activeTab` (`approvals` / `assignments` / `requests`, opens on `assignments`), `requestsFilter` (`open` / `done`), `assignmentsFilter` (`upcoming` / `all`), `loading` / `loaded` / `loadError`; `refresh()` loads the two lists together (shared in-flight promise, a failed list keeps its last value), `applyDecisionLocal`. My Assignments is not stored: `WorkView` derives it from `appStore.projects` with `collectMyAssignments` (`utils/myAssignments.ts`; approved rows of non-archived projects at every level, `upcoming` = end ≥ today, soonest first). In `resetAllStores()` |
| `confirmStore` | no | Queue of pending `confirmAction()` requests (first in shows); `ConfirmDialog` settles the head. Reset by `resetAllStores()`, which resolves every pending request `false` |
| `adminStore` | no | Admin portal: admin user + `mustChangePassword`, tenants, organizations, admin users, stats, active tab, `selectedTenantId` / `selectedOrganizationId`. Not re-exported from `stores/index.ts` and not touched by `resetAllStores()` |

Persistence gotchas: Sets are serialized as arrays and restored in custom `merge` functions. viewStore's `merge` is **field by field**, so every field added to `partialize` must also be listed in `merge`, or it silently resets on every reload. `currentDate` and `timelineScrollLeft` are memory-only — the app always opens on today.

### API client (`src/api/client.ts`)

- `apiRequest<T>` + `apiGet/Post/Put/Patch/Delete` + `downloadFile` (Content-Disposition-aware).
- Cookie auth (`credentials: 'include'`) — no token headers.
- Dev detection: when the page runs on port 3333, API and WS target `:8485` directly (no Vite proxy).
- FastAPI 422 validation errors are flattened to `field: message` strings; non-JSON responses raise with the first 200 chars logged (catches proxy HTML). Every non-2xx throws `ApiError` (an `Error` carrying `status`; `isForbidden(err)` for 403s). A 202 own-booking body is recognised with `isPendingResponse()` (`api/endpoints/approvals.ts`), never by status.
- **Session expiry**: a 401 on a session-bound call fires the `onUnauthorized` hook → `expireSession()` (`src/stores/index.ts`): `resetAllStores()` (appStore except the persisted site id, What-If, undo, notifications, custom-column data, `uiStore` back to its initial state, and the transient body classes `phantom-sibling-mode` / `resource-dragging` / `kanban-dragging` / `what-if-mode` removed; viewStore and column visibility are kept, adminStore is left alone) and back to the login screen. `useAuth.logout` also calls `resetAllStores()`, so nothing carries over to the next person on the tab. Add new stores to `resetAllStores()`.
- **What-If interception** happens here (see [What-If Mode](#what-if-mode)).
- Endpoint modules beyond the per-domain ones: `health.ts` (`getAppVersion()`), `importChunks.ts` (`postInChunks()`, used by `sites.ts` / `vacations.ts`), `kanban.ts` (+ `mentionableCache.ts`: `mentionableUsersFor(siteId, load)`, the @-mention list per site for the session, import-free, cleared by `resetAllStores` and by WS batches holding `staff` / `roles`), `notifications.ts`, `approvals.ts`. The last three are imported directly, not re-exported from `api/index.ts` (`roles.ts` is).

### Transform layer (`src/api/endpoints/projects.ts`)

All backend↔frontend field mapping is centralized. The frontend model is mostly snake_case like the API. Inbound, `transformProject/Phase/Subphase/StaffAssignment/EquipmentAssignment` map phase `type`→`name` and `sort_order`→`order_index`, reshape the tree (`subphases`→`children`, `parent_type`/`parent_id`→`parent_phase_id`/`parent_subphase_id`), camelCase the assignment arrays, map each staff assignment's `approval_status` (`pending` / `approved`), `approval` (the open request, or null) and `linked` (card rows; absent from an older server = linked with the card's dates; project rows `false`), default `status` to `todo`, and inject theme colors (`getPhaseColor`, `getDepthColor`). Outbound, only phase `name`→`type` is mapped. `fetchAllProjects()` fetches the list then each project detail in parallel; `loadAllProjects()` wraps it and is a no-op during What-If. Assignment CRUD routes differ by level (`/assignments/{id}` vs `/phase-staff/{id}` vs `/subphase-staff/{id}`) — the endpoint module picks the right one.

### Gantt architecture (`src/components/gantt/`)

- `GanttContainer` orchestrates: filters projects to the current site (non-archived), orders them with `orderSiteProjects()` (`utils/storage.ts`, shared with the Kanban board: per-site custom order from localStorage, default = confirmed-first, then name), applies the project filter (`useFilteredProjects`), memoizes timeline cells/headers, and renders **`ProjectPanel` (left tree) + resizer + `Timeline` (right)** inside `TimelineScrollProvider`, with optional embedded staff/equipment overview panels below (`canManageAnyProject`: `projects.edit_any`, or the PM of at least one project).
- `ProjectPanel/`: header actions, right-aligned across the name column + custom columns (new/import/manage columns/visibility/Filter — `ProjectFilterDropdown` from `components/common` (one section per dropdown field with an item at the site, "(None)" first, then "Tags"; options narrowed by the team filter, projects resolved against every site item and tag), also mounted in the Kanban toolbar — then `GroupByDropdown` (dropdown fields) and `ColorByDropdown` (dropdown fields + "Tags"), both thin wrappers over the shared `FieldChoiceDropdown` shell and rendering nothing without a choice; the header dropdown panels — and the column menus and Staff/Equipment overview filters — are `AnchoredPanel` portals aligned to their trigger, so an open overview pane cannot clip them) + `SectionRow` (Group-by section header) + rows `ProjectRow → PhaseRow → SubphaseRow → AssignmentRow` + custom-column cells; wrapped in `ReorderProvider`.
- `Timeline/`: `TimelineHeader` + `TimelineBody` — grid cells (weekend/holiday/company-event backgrounds; week separators when weekends are hidden), `TodayLine`, per-project bars (`ProjectBar`/`PhaseBar`), `DependencyLayer` (arrows), phantom overlays, `DragIndicator`, `ResourceDropOverlay`. Handles scroll persist/restore (200 ms debounce), zoom re-centering on the visible center date, view-mode changes preserving the left-edge date, Ctrl+wheel zoom, and scroll-to-today/date triggers.
- **Group by a project field**: `GanttContainer` turns `useGanttGrouping()` + the filtered projects into one flat `GanttRow[]` (`components/gantt/utils/projectSections.ts`: `buildProjectSections` → `buildGanttRows`; sections `field-<item id>` in item order, a project under its first item, empty sections omitted, "No <field>" last; the pill colour is the item's) and hands the **same array** to `ProjectPanel` (`SectionRow`) and `TimelineBody` (`div.groupBand`, a direct child of `.rows`); both panes fall back to a memoised flat list when `rows` is omitted. Section rows are `--section-row-height` (36 px) + 1 px border, content-box, = `SECTION_ROW_TOTAL_HEIGHT` (37) in `calculateRowPositions(rows, …)`, keyed `section-<key>`; collapsed sections' projects get no position (no arrows, no drop target). Section class names must not contain `row` and carry no `data-project-id`/`data-phase-id` (the drag/resize hooks and `DependencyLayer` find rows by `[class*="row"]` / data attributes). Project drag-reorder is off while grouped (`onProjectReorder` undefined).
- Scroll sync: `TimelineScrollContext` (horizontal, direct DOM with feedback-loop guard) across Gantt/Staff/Equipment timelines; `useScrollSync` (vertical) between tree panel and timeline body — wheel-driven in the same frame, echo-free, and padding the shorter pane so both reach the same scroll end (never a fixed scrollbar-height padding in CSS).
- **Drag pipeline** (`useDragAndDrop`): mousedown or touchstart on a bar (touches become a mouse-like event via `toMouseLikeEvent`) → live DOM movement with cell snapping (week/month) and a dependency lag indicator → on drop, `commitDragUpdate` computes new dates from pixels, awaits `confirmAction()` for whole-project moves (cancel snaps the bar back), snapshots undo state, clones and mutates the project tree (cascading children + project-level assignments — pending project rows are never moved; a moved or resized card fits its own bookings **locally only** with `fitCardBookings(card, oldStart, oldEnd)` (linked rows take the card's dates, unlinked ones are translated/clamped, pending ones too) and sends no segment PUTs, the server fits them in the card PUT; every `PendingUpdate` carries its assignment `level`, so a staff update goes to the right route), updates the store optimistically, then persists via batched `PendingUpdate`s (`savePendingUpdates`, in **two waves**: project/phase/subphase updates first, then staff/equipment assignment updates, so a segment PUT never precedes its card's; every update is tried, failures reported together). **Any persist error → reload all projects + clear undo.** The document `mousemove`/`mouseup` **and `touchmove`/`touchend`/`touchcancel`** listeners (here and in `useResize`) are attached at drag start and removed on mouse-up/touch-end and on unmount — never left on the document between drags. Touch: the bars hand the hooks a mouse-like event built by `utils/touchEvents.ts` (`toMouseLikeEvent`, an explicit object — never spread a SyntheticEvent, its methods are lost; its `preventDefault` is a no-op for the passive touchstart), and every touch start waits for a 5 px move first (`armTouchGesture` for project, assignment and resize-handle touches; the PhaseBar body has its own threshold) so a wobbly tap never commits a move; the non-passive `touchmove` listener calls `preventDefault()` only on interactive bars (React's root `touchstart` listener is passive, so only CSS `touch-action: none` on the *interactive* bars — the `interactive` class, set when a bar has drag/resize handlers, so read-only bars still scroll — plus that listener stop the timeline from scrolling), `touchend` is default-prevented so the browser sends no emulated click, and `touchcancel` restores the bar without saving (`cancelDrag`/`cancelResize`).
- **Auto-calculation semantics** (`gantt/utils/autoCalculation.ts`): dependencies auto-align **only at creation time**; moving an item does *not* cascade to its dependents (users keep manual lead/lag control). Moves do (a) expand/contract parents to the union of their children and (b) auto-fit project dates to phases. Staff-assignment updates must include `allocation` (backend requirement).
- **Critical path** (`components/gantt/utils/criticalPath.ts`): full CPM forward/backward pass, `totalFloat <= 0` = critical; loaded via dynamic import from `appStore.toggleCriticalPath` to avoid a circular dependency.
- **Undo/redo** (`useUndoRedo` + `components/gantt/utils/diffProjects.ts`): restore snapshot, diff old-vs-new date fields **and dependency arrays** into minimal `PendingUpdate`s (pending assignment rows skipped; unlinked phase/subphase rows diffed with their level by calendar day, a row unlinked since the snapshot gets a `relink` update and one linked since gets its dates again), persist; on failure reload + clear history.
- **Pending bookings**: a pending create (`isPendingAssignment`) renders as a dashed `AssignmentRow` / hatched `AssignmentBar` with a `PendingBadge`, a row with an open change shows `40% → 60%`; any open request freezes the bar. The context menu offers Approve / Reject (`approval.can_decide`) and Cancel request (the requester); Edit follows `assignmentLock` (`utils/pendingBookings.ts`): someone else's pending create, a row carrying my own open request, or no edit right lock it; `AssignmentModal` applies the same rule and opens read-only with a `Notice` (`ASSIGNMENT_LOCK_MESSAGES`), comments still usable — My Work's Open always opens the dialog. A 202 from a write goes through `utils/pendingBookings.ts` (`markRequestPendingLocally`, `reloadAfterPendingWrite`, `flashSentForApproval`).
- **Card bookings (linked / unlinked)**: phase/subphase staff bars (`CardBookingBar` in `ProjectTimeline.tsx`) are drawn at `bookingSpan(row, card)`; a **linked** bar is read-only, an **unlinked** one is `interactive` when `canEditAssignment` allows it and drags/resizes within its card: the bars pass `{level, bounds}` (`CardBookingDrag`, last argument of `startStaffAssignmentDrag`; `DragData.level` / `bounds`), the hooks clamp live with `clampToCard` (pixel via `gantt/utils/timelinePixels.ts`), skip the lag indicator, clamp again at commit and PUT with the level; a refused booking write is flashed with the server's text. Every booking row's card badge is one rectangle, `CardBadge` (`ProjectPanel/CardBadgeView.tsx`; styles and name from `cardBadge.ts`), holding two buttons: the **pin toggle** (`PinIcon` filled = linked, `PinOffIcon` outlined = own dates; `aria-pressed`; always drawn, `disabled` when the user may not edit the row, it is pending, their own request on it is open or the card has no dates; also, with the title *Can't follow the phase dates while another booking of this person overlaps them*, on an unlinked row whose relink the server would refuse with a 409 — `relinkWouldOverlap(row, card.staffAssignments, card)` in `staffGroups.ts`, computed by `CardStaffRows`; unlinking is never blocked): unlink sends the card's dates, relink `null` dates, with undo state saved, a 202 → `markRequestPendingLocally`; and the **card name**, which scrolls the timeline to the booking (`triggerScrollToDate` of the own start when unlinked, the card start when linked). Both stop propagation, so a click never reaches the row (a right-click still opens its menu). `AssignmentModal` has the matching "Follow the phase/subphase dates" `ToggleSwitch` (off → `DateRangeField` with `minDate` / `maxDate` = the card; a card moved while a new booking is open restarts dates now outside it on the card). For a new booking the switch is **reactive until touched** (`followCardChoice` is `null`, `followCard = followCardChoice ?? secondBooking`): a first booking opens unpinned with the card's dates prefilled and sent; picking someone already on the card turns it on. New bookings from the dialog with the switch on (also opened by the context menu's "Assign me…" / "Request to assign me…" and their "again…" forms, `modalContext.staffId` = the user) and a resource drop are sent without dates: linked when the person has no row on the card, otherwise placed by the server (`plan_placement`: largest free gap, or the half of a full-span booking); Kanban's assignee POST is placed too, but a first booking there gets the card's own dates (`link_first=False`).
- **Overview row**: a person with 2+ bookings on one card gets a `StaffGroupRow` (panel, indented like a booking row: chevron, the same `CardBadge` rectangle without the pin — its name scrolls to the person's earliest booking (`firstStart` from `CardStaffRows`, the earliest `bookingSpan` start) —, name, "N bookings", allocation range) whose timeline row is a read-only `SegmentsBar` (one block per booking, pending ones hatched, tooltip `name · dates · N%`), followed by the per-booking rows while expanded. The layout rule is one: `gantt/utils/staffGroups.ts` (`cardStaffItems(assignments, level, card, collapsed)` — a group sits where the person's first row comes in API order, its rows in date order (`bookingSpan` start, then id) —, `staffRowCount`, `staffGroupKey`, `allocationRange`, `relinkWouldOverlap`) feeds `CardStaffRows` (panel), `CardStaffBars` (timeline) and `calculateRowPositions` alike. Group rows carry no `row` class and no `data-*-id`, so the drag/resize hooks and `DependencyLayer` never target them; they have no context menu.
- **Dependencies** are stored per phase/subphase as JSON `[{id, type, lag?, entity?: 'phase'|'subphase'}]`. Phase and subphase ids are separate sequences, so new links always write `entity`; legacy entries without it resolve **phase-first**. Always go through `components/gantt/utils/dependencies.ts`: `resolveDependencyPredecessor` (lookup), `dependencyMatches` (find/delete a link, legacy-aware, missing `type` = FS), `wouldCreateDependencyCycle` (walks phases and subphases alike). Arrows, critical path and linking all use them.
- **Timeline headers**: generated in `components/gantt/utils/timeline.ts` (`generateTimelineCells` / `generateTimelineHeaders`); week labels are ISO 8601 (date-fns `getISOWeek` / `getISOWeekYear` — 1–3 Jan 2027 is W53); the current month is highlighted.
- **Custom-column cells** write one value with `setCustomColumnValue`, and a cascade to children with `setCustomColumnValuesBatch` (chunks of ≤ 500, the backend limit); on failure the touched cells are rolled back unless edited again since.

### Kanban architecture (`src/components/views/KanbanView/`)

- The board is a second rendering of the Gantt tree, not a separate dataset: `KanbanView` takes `appStore.projects`, orders them with `orderSiteProjects()`, filters with `useFilteredProjects()`, and derives cards with `utils/kanbanCards.ts` (card = leaf phase/subphase, milestones included; `groupCards()` builds the swimlanes for the `viewStore.kanbanGrouping` choice). `KanbanBoard` → `KanbanColumn` → `KanbanCard`; `KanbanToolbar` holds the project picker, grouping (no project fields), Filter and My-to-do toggle.
- Comment counts come from `api/endpoints/kanban.ts` (`getCommentCounts` for one project, `getSiteCommentCounts` in "All projects" mode); the card dialog is `modals/KanbanCardModal.tsx` (assignees with `AllocationSlider`, the thread in `common/CardComments` — `MentionTextarea`, mention candidates from `getMentionableUsers` through `mentionableCache.ts`, its own submit guard). The same `CardComments` sits in `AssignmentModal` (edit mode, staff) for the card's thread or, at project level, the project's thread; it renders after the `<form>` and every button in it is `type="button"`, so a Comment click never submits the booking.
- A card shows one avatar per person (`groupCardBookings`; dashed only while none of their rows is approved, title lists every allocation), and `KanbanCardModal` lists one line per booking (segment dates on unlinked rows) whose ✕ removes **that row** through `deleteStaffAssignment(row.id, level)` — `unassignCard` stays exported but unused (the per-person route 409s on several rows).
- Assignees are approved rows only (`assigneeIdsOf`); pending ones (`pendingAssigneeIds`) show as dashed avatars, count for **My Todo**, but never make a card movable or due-reminded. `KanbanCardModal` relabels Join / leave / slider writes in approval mode and shows `ApprovalActions` to deciders.
- Dragging is `contexts/KanbanDragContext.tsx` — hand-rolled HTML5 drag events like `ReorderContext` and `useResourceDragDrop`, no DnD library. The move is optimistic; the server echoes `{status, completion}` and the client reconciles without a refetch.
- Server writes broadcast as `phase` / `subphase` / `staff_assignment` / `card_comment` (see [Real-Time Collaboration](realtime.md)); a card status change from the Gantt slider is applied locally by `statusAfterCompletionWrite` because the rich broadcast excludes the sender.

### Hooks catalog (`src/hooks/`)

## What-If Mode

A client-side planning sandbox — the server is never aware of it.

- Entering (`WhatIfToggle`, shown with `whatif.use` — admins and superusers by default → `whatIfStore.enterWhatIfMode`) snapshots `appStore.projects` via `structuredClone`; `TenantApp` adds the `what-if-mode` body class while the flag is on.
- While active, the **API client** intercepts every POST/PUT/PATCH/DELETE (exemption list: see [What-If exemptions](conventions-in-depth.md#what-if-exemptions)): the request is queued as a `WhatIfOperation {id, method, url, body?, timestamp}` and a fake success `{success: true, whatIfMode: true, id: Date.now()}` is returned, so optimistic local state updates normally.
- **Discard**: restore the snapshot, drop the queue. **Apply**: temporarily disable the interception check (always restored in `finally`), replay queued operations sequentially with real requests, then reload from the server (`fetchAllProjects()`) and exit. **On the first failure Apply stops**: the failed and remaining operations stay queued, What-If stays **active**, projects are reloaded from the server and the snapshot is reset to that state (so a later Discard restores what really landed), and `whatIfApplyError {applied, total, message}` is set — `WhatIfToggle` shows it as a header banner with **Retry / Discard / Dismiss** (`dismissApplyError`), not an alert. Interception is back on during the post-Apply reload, so edits made in that window are queued and **kept** (appended after the remaining operations; on success What-If stays active with just those). If the stores were reset meanwhile (401 → `expireSession`, logout), Apply leaves them reset.
- Undo history is cleared on enter, Discard and Apply (its snapshots straddle the sandbox boundary); undo/redo *inside* What-If persists through the API client, so it is queued like any edit.
- `loadAllProjects()` is a **no-op during What-If** (returns the local projects) — every "reload after a write" goes through it, so a reload never wipes the sandbox. Use `fetchAllProjects()` when a real fetch is required. Consequently an edit must update the store locally (optimistically, or with `utils/localProjectTree.ts` after the queued call) or it stays invisible until Apply.
- **Gantt-only.** `Header.tsx` renders `WhatIfToggle` only while `currentView === 'gantt'` (or a sandbox is already open). While What-If is active, view switching and the Settings hub are blocked in two layers: store guards (`viewStore.setCurrentView` accepts only `'gantt'`; `uiStore.openSettings`, `setActiveModal('settingsHub')` and the legacy `openModal` settings aliases are no-ops) cover every present or future caller, and `useWhatIfBlocked()` visibly disables the controls with the reason. That covers `Sidebar/Navigation.tsx`, the Kanban deep link in `NotificationBell.tsx`, and every Gantt-reachable entry point: `AdminSection`, the project dialog's "Manage tags…" / "Manage fields…" (`ManageSettingsLink`), and the embedded Staff view's `BankHolidaysRow` / `CompanyEventsRow`. The Delete buttons in `EquipmentPanel`/`UsersPanel` are disabled too (their bookings are plan data), and so are the holiday/event deletes in the embedded rows (calendar data is not in the snapshot, and the refetch after a queued delete would resurrect the row). Nothing is auto-discarded. Keep new navigation or Settings entry points behind the same hook.
- **Creates are blocked during What-If** (a queued POST has no server id, and the new item could only appear after Apply): Phase/Subphase/Project dialogs and the Assignment dialog in create mode, absences (`VacationModal`, `MyAbsencesModal`), equipment blocks (`EquipmentBlockModal`), Kanban "add assignee"/"join", resource drops on the timeline and the context-menu "Add …"/"Assign …"/"Assign me…" items are disabled via `useWhatIfBlocked()` / `whatIfUnavailableMessage()` (same wording as the import dialogs). Edits and deletes stay allowed, except holiday/event deletes in the Staff view rows (not snapshotted).
- Project and custom-column WebSocket refreshes are deferred until What-If ends (see [Real-Time Collaboration](realtime.md#frontend)).
- Implications for new code: any new write endpoint is queued by default (see [What-If exemptions](conventions-in-depth.md#what-if-exemptions)); operations that depend on real server responses (created IDs used by later operations) do not work correctly inside What-If — the queue replays with the original bodies. New create entry points must be blocked the same way.
- Known limitations: MPP import uploads via a raw `fetch` that bypasses the queue, so `ImportProjectModal` blocks importing while What-If is active. `.ics` calendar imports (`ICSImportPanel`: holidays, events, absences) are blocked too — calendar data is not part of the What-If snapshot. Custom-column *definition* changes are queued but live in `customColumnStore`, which is not snapshotted — a definition created/deleted during What-If is not rolled back locally on Discard (reload to resync). Configuration edits (tags, project fields and their items, absence types, skills, equipment types, phase templates, users, site and equipment definitions — see the exemption list in [What-If exemptions](conventions-in-depth.md#what-if-exemptions)) bypass the queue entirely; the Settings hub and the equipment/user Delete buttons are unreachable during What-If, so a cascading delete (site → projects, equipment → bookings, user → assignments) cannot desync the sandbox from the UI — a delete issued another way (another tab, the API) still does, and the deferred refresh resyncs once What-If ends. A queued project edit holding a tag or field item an admin meanwhile limits to other sites/teams fails on Apply with the backend 400 (Retry cannot fix it — Discard that edit); a deleted field or item is dropped silently. Own bookings stay queued: a queued own edit or removal whose key is in approval mode looks applied in the sandbox, and on Apply the server answers 202 and files an approval request instead (no "needs approval" hint is shown before Apply). Roles, approval policies, approval decisions and comments are exempt (see [What-If exemptions](conventions-in-depth.md#what-if-exemptions)); Approve / Reject / Cancel request are disabled while What-If is active, because the post-decision reload is a no-op there (My Work itself is unreachable; the booking dialog's comments still post).
